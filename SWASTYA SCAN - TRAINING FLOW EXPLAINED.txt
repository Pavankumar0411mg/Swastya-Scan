SWASTYA SCAN - TRAINING FLOW EXPLAINED FOR BEGINNERS
=====================================================

Before we start, let's understand one simple idea:
  "Training" means teaching a computer to recognize patterns
   by showing it thousands of examples, just like how a child
   learns to identify animals by seeing many pictures of them.

Swastya Scan trains TWO separate models:
  1. Skin Disease Model  → learns from IMAGES
  2. Heart Disease Model → learns from NUMBERS (patient data)

Let's go through each one step by step.


=======================================================
PART 1: SKIN DISEASE MODEL  (training/skin_model.py)
=======================================================

GOAL: Look at a photo of skin → identify which disease it is
      from 10 possible diseases.

-------------------------------------------------------
STEP 1: SETTING UP BASIC RULES
-------------------------------------------------------

  IMG_SIZE   = 224   → Every image will be resized to 224x224 pixels
  BATCH_SIZE = 32    → Train on 32 images at a time (not all at once)
  EPOCHS     = 20    → Go through the entire dataset up to 20 times

  Think of EPOCHS like reading a textbook 20 times to memorize it better.
  Think of BATCH_SIZE like studying 32 pages at a time instead of all at once.

-------------------------------------------------------
STEP 2: LOADING THE DATASET
-------------------------------------------------------

  The skin images are stored in folders like this:
    datasets/skin/
      Acne/           ← all acne images go here
      Eczema/         ← all eczema images go here
      Lupus/          ← all lupus images go here
      ... (10 folders total, one per disease)

  TensorFlow reads these folders automatically.
  The folder name becomes the label (answer) for each image.

  The data is split into two parts:
    - Training set   (80%) → used to TEACH the model
    - Validation set (20%) → used to TEST if the model is learning correctly

  Seed=123 ensures the split is the same every time you run it
  (so results are reproducible).

  "prefetch" is used to load the next batch of images while the
  current batch is being trained — this speeds up training.

-------------------------------------------------------
STEP 3: USING A PRETRAINED MODEL (Transfer Learning)
-------------------------------------------------------

  Instead of building a brain from scratch, we borrow a brain
  that already knows how to look at images — MobileNetV2.

  MobileNetV2 was trained on ImageNet, a dataset of 1.2 million
  images across 1000 categories (cats, cars, flowers, etc.).
  It already knows how to detect edges, shapes, textures, and patterns.

  We load it with:
    weights = "imagenet"     → use the already-learned knowledge
    include_top = False      → remove its original final layer
                               (we don't want it to predict cats/cars)
    input_shape = (224,224,3)→ expects 224x224 color images (3 = RGB)

  base_model.trainable = False
    → We FREEZE MobileNetV2's weights.
    → It will NOT change during our training.
    → We only train the new layers we add on top.

  This is called TRANSFER LEARNING:
    "Use knowledge learned from one task to help with a new task."

-------------------------------------------------------
STEP 4: ADDING OUR OWN CLASSIFICATION HEAD
-------------------------------------------------------

  On top of the frozen MobileNetV2, we add new layers:

  [MobileNetV2 output]
        ↓
  GlobalAveragePooling2D
    → Converts the 3D feature map into a single 1D vector.
    → Like summarizing a whole page into one sentence.
        ↓
  BatchNormalization
    → Normalizes the values so training is more stable.
    → Like making sure all students score on the same scale.
        ↓
  Dense(128, activation="relu")
    → A fully connected layer with 128 neurons.
    → Learns which features matter for skin disease detection.
    → ReLU means: if value < 0, make it 0. Keeps only useful signals.
        ↓
  Dropout(0.3)
    → Randomly turns off 30% of neurons during training.
    → Prevents the model from memorizing (overfitting).
    → Forces it to learn general patterns, not just memorize examples.
        ↓
  Dense(10, activation="softmax")
    → 10 output neurons, one per disease class.
    → Softmax converts raw scores into probabilities (all add up to 100%).
    → Example output: [Acne: 72%, Eczema: 15%, Lupus: 3%, ...]
    → The highest probability = predicted disease.

-------------------------------------------------------
STEP 5: COMPILING THE MODEL
-------------------------------------------------------

  Before training, we configure how the model will learn:

  Optimizer: Adam (learning_rate=0.0001)
    → Adam decides how much to adjust the model after each mistake.
    → Learning rate 0.0001 = take very small steps (careful learning).
    → Too large = overshoots. Too small = learns too slowly.

  Loss: Sparse Categorical Crossentropy
    → Measures how WRONG the model's prediction is.
    → If the model says "Acne: 10%" but the answer is Acne,
      the loss is HIGH. The model gets penalized.
    → Training tries to minimize this loss over time.

  Metrics: Accuracy
    → Simply counts: out of all predictions, how many were correct?

-------------------------------------------------------
STEP 6: CALLBACKS (Smart Training Controls)
-------------------------------------------------------

  Two automatic helpers are set up:

  ModelCheckpoint:
    → Watches val_accuracy after every epoch.
    → Saves the model ONLY when val_accuracy improves.
    → So we always keep the best version, not the last version.

  EarlyStopping (patience=5):
    → Watches val_loss after every epoch.
    → If val_loss doesn't improve for 5 epochs in a row → STOP training.
    → Restores the best weights automatically.
    → Saves time and prevents overfitting.

  Example:
    Epoch 1:  val_loss = 0.80  ← improving, continue
    Epoch 2:  val_loss = 0.65  ← improving, continue
    Epoch 3:  val_loss = 0.70  ← got worse (count: 1)
    Epoch 4:  val_loss = 0.72  ← got worse (count: 2)
    ...
    Epoch 7:  val_loss = 0.75  ← got worse (count: 5) → STOP!

-------------------------------------------------------
STEP 7: TRAINING
-------------------------------------------------------

  model.fit(dataset, validation_data=val_dataset, epochs=20, callbacks=[...])

  What happens in each epoch:
    1. Feed 32 images (one batch) into the model
    2. Model makes predictions
    3. Compare predictions to correct answers → calculate loss
    4. Backpropagation: adjust weights to reduce the loss
    5. Repeat for all batches
    6. At end of epoch: test on validation set
    7. Print training accuracy and validation accuracy
    8. Callbacks check if model improved → save or stop

  After training: model is saved as skin_model_new.keras

-------------------------------------------------------
VISUAL SUMMARY - SKIN MODEL TRAINING
-------------------------------------------------------

  Images in folders
       ↓
  Resize to 224x224, normalize pixels
       ↓
  Split: 80% train / 20% validation
       ↓
  MobileNetV2 (frozen) → extracts features
       ↓
  Our custom layers → learn disease patterns
       ↓
  Predict → compare to correct label → calculate loss
       ↓
  Backpropagation → update our custom layer weights
       ↓
  Repeat for 20 epochs (or until early stopping)
       ↓
  Save best model → skin_model_new.keras


=======================================================
PART 2: HEART DISEASE MODEL  (training/heart_model.py)
=======================================================

GOAL: Given 13 numbers about a patient → predict if they
      have heart disease (1) or not (0).

This is NOT an image problem. It's a table/spreadsheet problem.
We use a completely different approach: XGBoost.

-------------------------------------------------------
STEP 1: LOADING THE DATASET
-------------------------------------------------------

  The dataset is heart.csv — a spreadsheet with rows like:

  age | sex | cp | trestbps | chol | fbs | restecg | thalach | ... | target
   63 |  1  |  3 |   145    | 233  |  1  |    0    |   150   | ... |   1
   37 |  1  |  2 |   130    | 250  |  0  |    1    |   187   | ... |   0

  Each row = one patient
  "target" column = 1 means heart disease, 0 means healthy

  X = all columns EXCEPT target  (the 13 input features)
  y = only the target column      (the answer we want to predict)

  The 13 features are:
    age         → patient's age
    sex         → 1=male, 0=female
    cp          → chest pain type (0-3)
    trestbps    → resting blood pressure
    chol        → cholesterol level
    fbs         → fasting blood sugar > 120 mg/dl (1=yes, 0=no)
    restecg     → resting ECG results
    thalach     → maximum heart rate achieved
    exang       → exercise-induced angina (1=yes, 0=no)
    oldpeak     → ST depression induced by exercise
    slope       → slope of peak exercise ST segment
    ca          → number of major vessels (0-3)
    thal        → thalassemia type

-------------------------------------------------------
STEP 2: SPLITTING THE DATA
-------------------------------------------------------

  train_test_split(X, y, test_size=0.2, stratify=y)

  - 80% of patients → training set (model learns from these)
  - 20% of patients → test set (we check accuracy on these)
  - stratify=y → ensures both sets have similar ratio of
                 sick vs healthy patients (fair split)
  - random_state=42 → same split every time (reproducible)

-------------------------------------------------------
STEP 3: FEATURE SCALING
-------------------------------------------------------

  StandardScaler normalizes all 13 features.

  Problem without scaling:
    age = 63,  cholesterol = 233
    The model might think cholesterol is more important
    just because its number is bigger. That's wrong!

  StandardScaler fixes this:
    new_value = (value - mean) / standard_deviation
    Result: all features have mean=0 and std=1

  Example:
    age 63 → becomes ~1.2
    chol 233 → becomes ~0.3
    Now both are on the same scale. Fair comparison.

  IMPORTANT:
    scaler.fit_transform(X_train) → learns mean/std FROM training data
    scaler.transform(X_test)      → applies SAME scale to test data
    (Never fit on test data — that would be cheating!)

  The scaler is saved as heart_scaler.pkl so it can be reused
  during prediction in the app.

-------------------------------------------------------
STEP 4: XGBOOST MODEL
-------------------------------------------------------

  XGBoost = Extreme Gradient Boosting

  Think of it like this:
    Imagine you have 300 simple decision trees.
    Each tree is a simple set of yes/no questions:
      "Is age > 55?" → yes → "Is cholesterol > 200?" → yes → "Heart disease"

    XGBoost builds these trees ONE BY ONE.
    Each new tree focuses on fixing the mistakes of the previous trees.

    Tree 1: Makes predictions, some are wrong
    Tree 2: Focuses on the cases Tree 1 got wrong
    Tree 3: Focuses on cases Tree 1 and 2 got wrong
    ...
    Tree 300: Final combined prediction is very accurate

  This is called BOOSTING — each model boosts the performance
  of the previous one.

  Settings used:
    objective = "binary:logistic" → output is a probability (0 to 1)
    eval_metric = "logloss"       → how loss is measured during training

-------------------------------------------------------
STEP 5: HYPERPARAMETER TUNING WITH GRIDSEARCHCV
-------------------------------------------------------

  Hyperparameters are settings we choose BEFORE training.
  We don't know the best values upfront, so we try many combinations.

  Parameters tested:
    n_estimators  : [100, 200, 300]  → how many trees to build
    max_depth     : [3, 5, 7]        → how deep each tree can grow
    learning_rate : [0.01, 0.05, 0.1]→ how much each tree contributes
    subsample     : [0.8, 1.0]       → fraction of data used per tree

  Total combinations: 3 × 3 × 3 × 2 = 54 combinations

  GridSearchCV tries ALL 54 combinations.
  For each combination, it uses 5-Fold Cross Validation:

  What is 5-Fold Cross Validation?
    Split training data into 5 equal parts (folds).
    Round 1: Train on folds 2,3,4,5 → test on fold 1
    Round 2: Train on folds 1,3,4,5 → test on fold 2
    Round 3: Train on folds 1,2,4,5 → test on fold 3
    Round 4: Train on folds 1,2,3,5 → test on fold 4
    Round 5: Train on folds 1,2,3,4 → test on fold 5
    Average the 5 accuracy scores → final score for this combination

  The combination with the highest average accuracy wins.
  That becomes best_model.

  n_jobs=-1 → use all CPU cores to speed up the search

-------------------------------------------------------
STEP 6: EVALUATION
-------------------------------------------------------

  After finding the best model, we test it on the 20% test set:

  accuracy_score → overall % of correct predictions

  classification_report shows:
    Precision → of all patients predicted as sick, how many actually were?
    Recall    → of all actually sick patients, how many did we catch?
    F1-score  → balance between precision and recall

-------------------------------------------------------
STEP 7: SAVING THE MODEL
-------------------------------------------------------

  joblib.dump(best_model, "heart_model.pkl")
  joblib.dump(scaler, "heart_scaler.pkl")

  joblib saves Python objects to disk so they can be loaded later.
  The app loads these files at startup to make predictions.

-------------------------------------------------------
VISUAL SUMMARY - HEART MODEL TRAINING
-------------------------------------------------------

  heart.csv (patient records)
       ↓
  Separate features (X) and labels (y)
       ↓
  Split: 80% train / 20% test
       ↓
  StandardScaler → normalize all 13 features
       ↓
  GridSearchCV → try 54 hyperparameter combinations
       ↓ (each with 5-fold cross validation)
  Pick best combination
       ↓
  Train final XGBoost model on full training set
       ↓
  Evaluate on test set → print accuracy + report
       ↓
  Save model → heart_model.pkl
  Save scaler → heart_scaler.pkl


=======================================================
KEY CONCEPTS SUMMARY FOR BEGINNERS
=======================================================

  Term                  | Simple Meaning
  ----------------------|------------------------------------------
  Training              | Teaching the model using examples
  Epoch                 | One full pass through all training data
  Batch                 | Small group of examples processed together
  Loss                  | How wrong the model's prediction is
  Accuracy              | % of correct predictions
  Overfitting           | Model memorizes training data, fails on new data
  Transfer Learning     | Reusing a model trained on a different task
  Dropout               | Randomly ignore neurons to prevent memorization
  Backpropagation       | How the model adjusts itself after a mistake
  Validation Set        | Data used to check learning (not used in training)
  StandardScaler        | Makes all numbers comparable (same scale)
  Cross Validation      | Testing on multiple splits for reliable accuracy
  Hyperparameter Tuning | Finding the best settings for the model
  GridSearchCV          | Automatically tries all setting combinations
  XGBoost               | Powerful method using many decision trees together
  MobileNetV2           | Lightweight image recognition neural network
  Softmax               | Converts scores to probabilities (adds up to 100%)
  Callbacks             | Automatic actions during training (save, stop early)
